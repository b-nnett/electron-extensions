## Harness corrections and validation

The earlier [sweep audit](../output/final-audit/report.json) incorrectly claimed that no additional-app main process remained. Compass changed its displayed process name to a basename, so full-path `ps` checks missed the live main process from the old trial and reported cleanup incorrectly. The [Compass diagnosis](../output/compatibility/compass/diagnostics/2026-09-05T22-59-41.159Z/diagnosis.json) records its identity and subsequent cleanup.

[Process identity](../lib/process-identity.mjs) now uses read-only macOS `libproc` calls through `/usr/bin/python3` to obtain the executable path, user and start time. Missing or unreadable identity is not treated as confirmed exit. Ownership is checked before operations and cleanup. Six kernel inventories before, during and after the two new Compass trials are referenced in the [confirmation](../output/compatibility/compass/diagnostics/2026-09-05T22-59-41.159Z/adapter-confirmation.json); both owned processes and their helpers exited, with temporary profiles removed.

The earlier interruption fix in [SessionLifecycle](../lib/session-lifecycle.mjs) preserves CDP while restoration/disposal is attempted, stops new work and records cleanup timing. These harness changes preserve the existing fixed target and cosmetic-CSS boundaries. They do not change vendor security settings.

The latest `npm test` run passed **41 tests**, with no failures; see the [saved log](../output/compatibility/claude/developer-mode-setup/npm-test.log). The owned-fixture diagnostic and Claude's three successful production CLI trials, including a fresh-process confirmation, are separate evidence. The fixture's JavaScript-button integration proof remains distinct from these fixed CSS adapters; not every catalog app was retested.
