# Owned fixture imported CSS/JS broker integration

The Style Lab Dock broker now selects imported mixed CSS/JavaScript packages and connects them to the owned renderer lifecycle. This implementation is restricted to the fixed Style Lab app; existing ChatGPT/catalog CSS selectors and their JavaScript guards are unchanged. It is product-path implementation, not evidence that another vendor app supports imported JavaScript.

`lib/dock-library.mjs` adds `selectFixtureExtensions` and `readFixtureExtensionLibrary`, retaining `selectFixtureCSS`/`readDockLibrary` for existing CSS callers. Enabled fixture records require unique UUIDs, at most 64 records and 32 files per record. Source labels are contained relative names, no more than 256 UTF-8 bytes, and are never read as paths. Package legacy fields must match the first source, with the filename stored as its basename. CSS is capped at 64 KiB including joins; separate JavaScript files total at most 256 KiB. Enabled whitespace-only selection is refused; no enabled records returns `hasContent: false`. JavaScript revisions hash ordered filename/source bytes, while the overall selection revision includes CSS and selected metadata.

`scripts/dock-fixture-session.mjs` starts `FixtureSession` with `enableImportedExtensions: true`. It removes previous resources before a changed selection, applies CSS, awaits `extensions.sync(jsExtensions)`, and only then publishes an active status. Disabling all source awaits JavaScript cleanup and stylesheet removal. CSS removal is still attempted if JavaScript cleanup fails; an uncertain JavaScript operation does not become a successful active revision. Existing owned-process identity checks and signature/baseline checks stay in the broker.

`report.json` and `status.json` include JavaScript state proof (IDs, immutable revisions, phases, generation, cleanup flags and filenames). Source reports include filename/byte counts, never script text. The owned Style Lab screenshots already captured by the CSS fixture proof remain; this change adds no application-console subscription or third-party screenshot path.

Controller `reapplied` events refresh status and the latest report proof through the serial broker loop, including the renderer generation, observed reapplication count and timestamp. Events for stale script revisions are discarded; failed states cannot become active. After `FixtureSession.stop()`, a recorded `extensionCleanupError` overrides any earlier cleanup success and forces an error verdict without copying the raw source/error detail into the report.

The dedicated `extension-logs.json` envelope is `{schema: 1, appKey, sessionID, droppedEvents, events}`. A native launcher output UUID is used as `sessionID`; old standalone CLI proof folders receive a generated UUID also recorded in status/report. Only attributed extension events from the fixture controller are accepted. Persisted sequences increase even if a document's local sequence resets. The file keeps at most 500 events and 512 KiB, tracks dropped events, rejects invalid metadata/messages over 4096 UTF-8 bytes, and writes atomically through exclusive new `0600` temporary files. Writes coalesce while one is pending, and log write failures remain visible to the broker rather than silently preserving an active status.

Validation: **23 Node tests passed** in [the focused and legacy test log](../../../output/release-review/2026-09-13/fixture-mixed-broker-unit-tests.log). Ten new tests cover mixed/JS-only selection, boundaries and identity rejection, unchanged vendor guards, CSS-before-JS ordering, cleanup after failure, source-free state proof, bounded private logs with reset sequences, write failure propagation, selecting stored source without filesystem lookup of its filename, stale versus current reapplication states, and stop-time cleanup failure overriding an earlier success. These tests use temporary files and fake sessions and do not launch an app. The coordinating root and native E2E owner are responsible for actual packaged launch, reload and UI proof after controller integration; this document does not claim that live proof is complete.
