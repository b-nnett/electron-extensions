# Release review 3: extension and runtime security

**Verdict: NO-GO for public release.** Two release conditions remain: remove unsolicited renderer recording from normal use, and resolve/document the trust and lifecycle boundary of TCP debugging. DMG packaging and updater cryptography are outside this review.

**Subsequent source fix:** the screenshot collection finding has since been addressed by a default-off diagnostic gate and transport checks; see [privacy fix and 68-test verification](privacy-fix.md). The findings below preserve the reviewed pre-fix behavior. This follow-up does not resolve the separate TCP or library-bound findings, and it does not claim live distribution to an already-running helper.

Reviewed the current local source on 13 September 2026. This is a defensive code audit, with synthetic tests and read-only kernel identity smoke tests. No production app was launched, attached to, restarted, modified, or probed. No exploitation was attempted. Findings below distinguish code-established behavior from unverified impact.

The screenshot finding is a proven product behavior, not a hypothesis about a hostile extension. These images can contain conversations, account names, code, or documents simply because they are visible in the selected app. Files use mode 0600, which is good, but confidentiality between OS users does not justify unexpected collection. The recording path is shipped: `scripts/lib/package-runtime.mjs:4` includes both brokers and line 39 copies them into the runtime. `macos/Sources/SettingsView.swift` has no recording preference. Existing historical proof requests explain why capture code exists; they do not make perpetual capture an appropriate public default. No private images were opened during this review.

The TCP finding is an established exposure/lifecycle concern, not a reproduced compromise. Loopback limits network reach; it does not bind a socket to this launcher or the user's identity. The broker verifies the server's process ownership, which prevents its own attachment from drifting to a different server, but does not authenticate all other debugger clients. The catalog's `PAGE_METHODS` at `scripts/dock-catalog-session.mjs:22` constrains this broker only. Chrome's own security guidance describes sensitive-data risks from debugging real profiles and recommends isolation; that supports the threat assessment, but Chrome's exact default-profile restrictions must not be assumed to apply to every Electron build. [Chrome security guidance](https://developer.chrome.com/blog/remote-debugging-port). Electron documents that `--remote-debugging-port` enables remote debugging. [Electron switches](https://www.electronjs.org/docs/latest/api/command-line-switches).

## Other findings and explicit limitations

- **P2 — The manager's library read is unbounded.** `macos/Sources/ExtensionLibrary.swift:197` reads the entire file with `Data(contentsOf:)` before decoding or validation. Validation caps each source/package and the log count, but not total records or aggregate library bytes. In contrast, the launcher and brokers stop at 64 MiB. A large legitimate or damaged library can therefore exhaust memory or block the main actor before a useful error appears. Use a bounded regular-file read consistent with runtime limits, and test oversized/truncated library recovery without replacing the user's file.
- **Trusted local CSS, not isolated extensions.** Imported CSS is passed directly to `CSS.setStyleSheetText` (`lib/catalog-stylesheet.mjs:238`, `lib/chatgpt-stylesheet.mjs:75`). There is no selector rewriting, CSS resource permission model, or URL/import filtering. This is consistent with customization, but the product should identify imported source as trusted code rather than imply Chrome-style isolation. Whether remote resource requests succeed depends on the target app's policies; this review did not test outbound requests or data access. Arbitrary JS execution is currently rejected by all production launch profiles, including mixed CSS/JS packages.
- **Local mutation races remain a hardening question.** Manifest import resolves references into the chosen folder and limits reads, but `macos/Sources/ExtensionLibrary.swift:119` and 130 inspect paths before `FileHandle` opens them. It does not bind containment checks to the subsequently opened descriptor as rigorously as `RuntimeResourceFiles` does. A same-user concurrent filesystem mutation was not reproduced and is not treated as an independent public-release blocker. The helper's adjacent configuration and external Node executable similarly assume trusted local storage; dependency distribution is being reviewed separately.
- **Source integrity is not a publisher authenticity claim.** The code verifies target signatures and compares bundle hashes before/after (`lib/integrity.mjs:16`, 46–54), which supports the requirement to preserve the original app. It does not pin each vendor's signing identity. This review found no reason to claim that a signature-preservation check authenticates an installed vendor app.

## Controls that are already effective

- Manifest version, required metadata, relative paths, duplicate references, UTF-8, file count, individual file size, total package size, and containment are checked (`macos/Sources/ExtensionLibrary.swift:94`, 116–140). Stored filenames become labels; brokers read stored text, not source paths.
- Production selections filter by exact app key and enabled state, reject JS/unknown source types, and limit combined CSS to 64 KiB (`lib/dock-library.mjs:24`, `lib/catalog-stylesheet.mjs:82`). Package/legacy first-source inconsistencies fail rather than silently select different content.
- Runtime profiles constrain executable locations, transport flags and anchored renderer routes. Code excludes arbitrary endpoint/flag overrides, verifies kernel PID/start/executable/user identity, and rejects ambiguous target selection. Renderer navigation invalidates the owned stylesheet. Stylesheet readback verifies the text that was actually applied.
- Runtime dependency copying excludes the checkout's user evidence; runtime tree validation rejects symlinks/nonregular files and uses bounded descriptor reads with node identity checks (`macos/Shared/RuntimeResourceFiles.swift:41`). Manager preparation verifies and signs only its generated helper, then checks the copied runtime digest (`macos/Sources/ElectronLauncher.swift:368`, 413–455).
- Production brokers discard normal app stderr after recognizing startup endpoint metadata. Catalog target URLs are hashed in reports rather than retained in clear text. Session JSON and PNG writes request mode 0600. These controls reduce exposure, but do not repair unsolicited screenshots.
