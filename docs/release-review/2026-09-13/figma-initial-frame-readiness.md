# Figma initial committed-frame readiness

Candidate 13 native Figma run `DF282E3D-9555-42BC-ABA9-D2683F609C13` failed before any source application. Target discovery found one eligible page, attached that pinned target, and then `CatalogStylesheet.init()` immediately rejected its committed frame as outside the fixed route. The broker recorded no revisions and preserved the full installed signature/fingerprint. Pipe cleanup completed and the target exited normally, consistent with the documented pipe-close behavior.

The broadened exact HTTPS origin can expose a pending target earlier than the former exact `/login` match. `TargetInfo.url` can describe a pending navigation before `Page.getFrameTree` reflects the committed page. A blank initial frame is therefore a plausible cause, but **the failed run did not record the rejected frame URL**, so this is an inference rather than a confirmed about:blank observation. Its target URL SHA256 did not match the plain root or plain `/login` strings tried; a query-bearing route cannot be identified from that hash alone. No target or off-origin allowance was broadened further.

Candidate 14 added a bounded **initial attachment only** readiness check. Domain enablement may occur, but no stylesheet mutation, Runtime admission or imported source execution begins before the committed frame passes the unchanged route guard. Only an actual root frame with an empty URL or exactly `about:blank` may be retried. Every attempt revalidates the selected target's exact identity, current process ownership and unique eligible route; target replacement/ambiguity, ownership failure, malformed frames and committed off-origin frames remain immediate failures. The existing startup deadline bounds waiting, and status heartbeats remain fresh.

Normal frame checks during application/reload still reject outside-route or blank documents; this change does not authorize source on a transitional page. `report.initialFrameReadiness` records attempts and safe classification of a rejected frame (protocol, hostname and URL SHA256), never paths, queries, page contents, screenshots or extension source. That makes a repeated failure diagnosable without silently guessing its cause.

`tests/catalog-stylesheet.test.mjs` adds three deterministic synthetic cases: blank→allowed commit without source admission; immediate off-origin rejection with bounded route-only diagnostics; and deadline/target-ambiguity refusal while waiting. The [full Node suite](../../../output/release-review/2026-09-13/figma-initial-frame-full-node-tests.log) passed **259/259 tests**, with no failures or skips. The subsequent candidate 14 run still failed; the following section records its newly identified sentinel and the focused candidate 15 correction. Claude's completed candidate13 proof and all frozen notarized artifacts remain separate and unchanged.
