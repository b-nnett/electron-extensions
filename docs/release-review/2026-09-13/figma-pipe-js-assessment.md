## Concrete implementation gaps

1. **PipeCDP is deliberately CSS-only.** [lib/pipe-cdp.mjs:9](../../../../lib/pipe-cdp.mjs#L9) has no Runtime methods or `Page.createIsolatedWorld`; [line 95](../../../../lib/pipe-cdp.mjs#L95) forwards named events only for Page/DOM/CSS/Target. Merely enabling Figma in the catalog selector would fail controller initialization, and adding methods alone would still lose context/console events.
2. **The checked-in Figma route is login-only.** `compatibility/runtime-profiles.json` matches only `https://www.figma.com/login`, with `button[type="submit"]`. That selector cannot establish readiness for `/files` or an editor. The JS-only broker path already avoids fixed-control inspection, but CSS-bearing packages still use the profile control.
3. **JavaScript capability and page checks are VSCode-only.** [lib/catalog-stylesheet.mjs:104](../../../../lib/catalog-stylesheet.mjs#L104) and [macos/Shared/RuntimeExtensionSelection.swift:21](../../../../macos/Shared/RuntimeExtensionSelection.swift#L21) must agree on an exact Figma identity/flags/route predicate. The native selection routine also separately restricts `.catalogMixed` to the VSCode identifier at line 102.
4. **The current broker owns one root.** [uniqueCatalogTarget](../../../../lib/catalog-stylesheet.mjs#L164) rejects multiple matches, and the broker revalidates the pinned target before every application. Figma can retain several WebContentsViews. A browser plus one editor is enough to make a broad route union ambiguous even within one window. Never switch to the first returned page as a shortcut.

## Minimum scoped change

Keep the existing executable, signature/process checks, owned stdio 3/4 pipe, flattened attached session, bounds, and graceful broker cleanup. No launcher flag beyond the ordinary pipe flag is necessary for the proposed route.

- Add an explicit **per-attached-session renderer-JS capability** to PipeCDP, default off. The broker grants it only after the exact Figma profile and selected root have passed their checks. Permit only `Runtime.enable`, `Runtime.evaluate`, `Runtime.compileScript`, and `Page.createIsolatedWorld` on that attached page session. Keep browser/sessionless Runtime calls, arbitrary target types, and all other commands rejected. Revoke the capability on detach/close.
- Forward the controller’s five Runtime context/console/exception events only for that authorized session, retaining its `sessionId`. Existing Page load/navigation events remain session-filtered by `catalogRendererPage`. Do not persist the pipe’s generic unfiltered event stream.
- Extend the exact native and Node mixed-selection predicates together: Figma name/ID, exact installed bundle/executable, `transport: pipe`, unique arguments drawn only from `--remote-debugging-pipe` (raw empty is valid before normalization), no owned local service, and the precise reviewed target configuration.
- Reuse `RendererScriptController`, `selectRendererExtensions`, the existing mixed broker flow, and the app/session-bound log writer unchanged. Generalize the VSCode-specific scope/error text when the profile is Figma. The existing flattened-session wrapper already supports a pipe; the missing support is below it in PipeCDP.
- **Choose the first normal scope deliberately:** one Figma file-browser root on exact HTTPS `www.figma.com`, with `/files` and a bounded `/files/...` path family after live route observation. Exclude other origins, credentials, ports, local shell/preview, community, authentication callbacks, exports, and editors in this first pass. Reject ambiguous file-browser roots. Query/hash values may be used by the application but must not be written into evidence/logs.
- Login CSS compatibility and normal file-browser JS require a small explicit route/control decision. One possible first profile is login-or-files, with `body` as a neutral unique CSS readiness/readback anchor, and a stricter JS-page predicate for the reviewed routes. Validate this on both pages before replacing the current submit-button anchor; CSS readback alone must not be labelled a visual button-change proof. Alternatively retain the old login profile as historical verification and make the product Figma profile explicitly file-browser-only. A login-only JS pass is a useful transport smoke test but cannot close normal-workspace acceptance.

The shared controller already creates an isolated world with `grantUniveralAccess: false`, evaluates with `uniqueContextId`, and sets `allowUnsafeEvalBlockedByCSP: false`. Preserve these choices. Chromium documents flattened target sessions and page-world creation; its Runtime schema specifically describes context-ID reuse across processes and the CSP-bypass default. If Figma refuses these constrained operations, report that incompatibility instead of enabling a bypass. [Target protocol](https://raw.githubusercontent.com/ChromeDevTools/devtools-protocol/master/pdl/domains/Target.pdl), [Page protocol](https://raw.githubusercontent.com/ChromeDevTools/devtools-protocol/master/pdl/domains/Page.pdl), [Runtime protocol](https://raw.githubusercontent.com/ChromeDevTools/devtools-protocol/master/json/js_protocol.json).

Supporting every editor tab is a subsequent multi-target product change: one controller per explicitly qualified root, target lifecycle management, bounded aggregate log sequence/state, and truthful per-root coverage. Do not fold it into this single-root integration by relaxing ambiguity checks.
