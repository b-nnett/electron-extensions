# Release review 6 — test quality, evidence and release gates

Date: 13 September 2026. Scope: independent source, test and saved-evidence review; DMG packaging excluded. This review was completed while the root agent was adding Sparkle, so it does not certify that unfinished implementation.

**Verdict: NO-GO for a general public release.** The regression tests are useful and the evidence is substantially more honest than a simple compatibility count, but there is no demonstrated acceptance gate for the actual release candidate. A tightly scoped preview could be assessed after a fresh packaged-product smoke test and an observed update round trip; the older compatibility ledger cannot supply those results.

## Findings

| Priority | Finding and concrete evidence | Required release closure |
| --- | --- | --- |
| P1 | **Native E2E results are not bound to the shipping manager/helper build.** `scripts/catalog-native-e2e.mjs:119` records the target profile and trial time, but no manager bundle hash, helper executable hash, runtime digest, source revision or manager build number. `macos/Tests/CatalogLiveValidationTests.swift:44` combines newly compiled test-host manager code with resources from an independently built `dist` app. `scripts/update-e2e-ledger.mjs:45` validates target identity and evidence shape, not the manager/runtime build. Historical accepted rows intentionally survive subsequent unrelated trials (`tests/e2e-ledger.test.mjs:78`). Thus passing the ledger does not prove that the current shipping binary has been exercised. This is a release-evidence gap, not a claim that the historical trials were fabricated. | Bind the test host, running manager, generated launcher and broker resources to the same candidate identifier/digests. Run a fresh full product flow on that candidate, covering import, enable/disable, native restart, menu launch and cleanup, and retain its artifacts. Apply the gate to the declared supported release scope; narrowing that scope is more defensible than promoting partial results. |
| P1 | **An updater round trip remains a distinct unproven product behavior.** `scripts/catalog-native-e2e.mjs:121` explicitly records `actualUpdaterInstallTested: false`; `scripts/update-e2e-ledger.mjs:280` preserves that boundary. `docs/E2E-50-2026-09-08.md:38` describes a normal quit/reopen simulation rather than an actual update. The later restart regression proof (`docs/RESTART-AND-APPEARANCE-REGRESSIONS.md:27`) is an owned-fixture restart, not replacement of the manager by Sparkle. | After Sparkle integration, observe an old signed candidate discover and install a newer signed candidate from the configured feed, relaunch successfully, preserve the extension library/settings, and refresh existing helpers after they stop. Verify a tampered update is rejected in an isolated test. Retain both versions, feed and outcome evidence. This is an updater requirement, not DMG polish. |
| P2 | **No reproducible automated release-test gate was present at review time.** There was no `.github` directory. `package.json:8` builds the app independently of `package.json:10` and `package.json:14` test commands, so a successful build need not mean tests ran. Separate pure tests and fixture integration commands so headless or read-only invocations have predictable effects. If the new updater workflow supplies this, recheck this finding against that final workflow. |
| P2 | **Saved evidence is local and mutable rather than a durable release artifact.** `.gitignore:3` ignores all `output/`, yet `docs/E2E-50-2026-09-08.md:3` makes an `output` ledger authoritative and release-related docs link many files there. I found no retained minimum-OS launch/update/import smoke result. | Exercise the packaged candidate on the minimum supported OS and each distributed architecture, including updater initialization and native UI fallbacks, or explicitly narrow the supported release requirements to tested environments. ## What the tests establish well

- The current Node run passed **153 tests, zero failures and zero skips**, including the owned packaged Style Lab integration proof. That proof verifies actual computed CSS, reload/reapplication, click logs, removal and unchanged target signing; it is not just a snapshot or mocked assertion.
- Catalog evidence tests reject stale revisions, wrong extension IDs, recycled process IDs, changed signing, missing terminal cleanup and incomplete images (`tests/catalog-native-e2e.test.mjs`). Ledger tests explicitly keep background CSS results separate from full native E2E acceptance (`tests/e2e-ledger.test.mjs:41`) and require matching terminal reports (`tests/e2e-ledger.test.mjs:221`). These are meaningful failure-path checks.
- Native restart-alert tests inspect actual `NSAlert` objects and default/cancel actions (`macos/Tests/NativeRestartAlertTests.swift:7`). They do not claim a live alert was shown. The later Style Lab live report separately supplies that interaction evidence.
- The opt-in native test adapter defaults to skipping before live state access (`macos/Tests/CatalogLiveValidationTests.swift:26`) and clearly labels an action result as insufficient for CSS/menu/prompt/signing acceptance (`macos/Tests/CatalogLiveValidationTests.swift:37`). Its preservation checks protect unrelated library records.
- The saved current ledger is candid: two full E2E passes, separate partial CSS proofs, current failures, manual Claude coverage, and unsupported or pending routes (`output/e2e-50/2026-09-08/CURRENT-FINDINGS.md:5`). It also explicitly says earlier full passes are not retroactive proof for later manager changes at line 78. This review does not inflate those results into release coverage.

## Execution and limits

I ran `npm test`; its captured log is [06-node-tests.log](06-node-tests.log). The command completed in approximately 2.54 seconds with all 153 tests passing. I initially expected this to be a pure Node suite, but its unconditional `proof.test.mjs` launched the **owned packaged fixture** in an isolated profile and completed normal cleanup. The parent was notified. No third-party app/UI actions were performed. I did not run competing Swift builds, mutate the live user library or Dock, or run the catalog E2E adapter.

The **167 native tests, one intentionally skipped live test and zero failures** cited in `docs/RESTART-AND-APPEARANCE-REGRESSIONS.md:29` are saved prior-run evidence, not a newly executed native suite by this reviewer. Sparkle implementation and its subsequent tests must be reported separately by the root and updater reviewer.

This verdict focuses on proof and release gates. It does not duplicate the product-scope, lifecycle, extension-security, portability or UX reviewers' implementation findings.
